# Восстановление: PostgreSQL и векторный индекс

Разделение данных в платформе жёсткое (см. [Хранение](../README.md#хранение)),
и от него же зависит стратегия восстановления: одно надо бэкапить, другое —
пересобирать.

## Что персистентно, а что производно

| Компонент | Роль | Как восстанавливается |
|---|---|---|
| PostgreSQL | Источник истины: пользователи, базы знаний, права, документы, версии, диалоги, задачи индексации | Из дампа |
| Файлы документов (`storage/documents`) | Оригиналы под идентификатором; в БД — путь и контрольная сумма | Из бэкапа каталога |
| Qdrant | Производные данные: чанки только текущих версий | Переиндексацией из PostgreSQL и файлов |
| Redis | Очередь Celery | Ничего ценного не хранит |

Векторный индекс **не бэкапится**: его содержимое целиком выводится из
PostgreSQL (какие документы и версии существуют) и файлов на диске
(`storage_path`). Дамп Qdrant был бы вторым источником истины, который
пришлось бы отдельно согласовывать с первым.

## PostgreSQL: бэкап и восстановление

Бэкап — штатный `pg_dump`; схема берётся из миграций Alembic.

```bash
pg_dump --no-owner --no-privileges --format=plain \
  -f backup.sql "postgresql://rag:ПАРОЛЬ@localhost:5433/local_knowledge_rag"
```

Восстановление — разворачивание дампа в пустую базу той же схемы:

```bash
psql -v ON_ERROR_STOP=1 -d "postgresql://rag:ПАРОЛЬ@localhost:5433/local_knowledge_rag" \
  -f backup.sql
```

Проверяется тестом `tests/recovery/test_database_restore.py`: он собирает схему
миграциями, кладёт строки, задевающие enum, JSONB и внешние ключи, снимает
дамп, разворачивает его в **пустую** базу и сверяет конкретные значения, а не
код возврата команд. Дамп, который молча теряет таблицу или тип, выглядит
успешным до первого реального сбоя.

## Векторный индекс: восстановление переиндексацией

Бэкап не нужен — потеря коллекции Qdrant восстанавливается переиндексацией
документов из источника истины:

```bash
curl -X POST http://localhost:8000/documents/<document_id>/reindex
```

Проверяется тестом `tests/recovery/test_index_rebuild.py`: коллекция удаляется
целиком, пересобирается из исходных файлов, и результат сверяется с
источником — что документы на месте и что старых версий в пересобранном
индексе не осталось.

## Запуск тестов восстановления

```bash
uv run pytest tests/recovery
```

Оба теста интеграционные и требуют настоящих сервисов и утилит:
PostgreSQL + `pg_dump`/`psql` на `PATH` для базы, поднятый Qdrant — для
индекса. Без них тесты пропускаются, как и остальные интеграционные тесты
Qdrant.

## Что осталось за рамками

- Нет расписания бэкапов и метрик RTO/RPO — это эксплуатационная задача, а не
  свойство кода.
- Файлы документов лежат в `storage` (bind-mount) и в дамп PostgreSQL не
  входят: их каталог надо бэкапить отдельно, иначе после восстановления БД
  переиндексировать документы будет не из чего.
